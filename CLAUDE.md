Qt6 GUI client only — connects to a showeq-daemon over WebSocket. No pcap, no caps needed; AppImage's FUSE/squashfs file-cap stripping is therefore irrelevant here (it would matter for the daemon).
Local dev: `cmake -B build && cmake --build build`, then run `./build/showeq-qt`. The daemon URL is chosen in the in-app Connect dialog (default `ws://127.0.0.1:9090`, persisted in `Settings`) — there is no CLI url flag. Needs system Qt6 + `qt6-websockets-dev`; no proto submodule (`seq-proto` regenerates `.pb.cc` per build).
AppImage build: `cmake --build build --target appimage` produces `build/showeq-qt-*.AppImage`. Driver is `packaging/build-appimage.sh`; it fetches linuxdeploy + linuxdeploy-plugin-qt on demand into `build/tools/`.
CI publishes a rolling `continuous` GitHub prerelease on push to main, gated on ubuntu/fedora/windows/appimage jobs. Stable URL: `https://github.com/showeq-unofficial/showeq-qt/releases/download/continuous/showeq-qt-continuous-x86_64.AppImage`.
AppImage CI container is `debian:bookworm-slim` — do NOT use `ubuntu:22.04` (jammy lacks `qt6-websockets-dev`; only in noble/24.04+). Bookworm has it and keeps glibc at 2.36 for broad distro coverage. Set `APPIMAGE_EXTRACT_AND_RUN=1` in GHA containers (no FUSE).
Windows CI uses `jurplel/install-qt-action` for prebuilt Qt6 + a from-source protobuf build cached by tag. vcpkg was removed because (a) Qt6 was 90% of the time and (b) microsoft retired the `x-gha` binary cache backend, so `lukka/run-vcpkg` rebuilt every run (~2.5h). Bumping the protobuf tag invalidates the cache; first build after that takes ~7-10 min, subsequent ~2-3 min.
Linux jobs use system Qt6 + system protobuf (versions vary by distro). `seq-proto` regenerates `.pb.cc` per build, so cross-platform protobuf-version drift is cosmetic.
`ctest` runs on the two Linux CI jobs only. The test target (`concolor_test`) is opt-in on `find_package(Qt6 COMPONENTS Test)` so a qtbase split without Qt6::Test still builds the app.
Con colors live in `src/util/ConColor.h` and are **derived from the EQ client's runtime con table**, not from legacy showeq's hand-tuned ladder. Three other ports of the same formula exist — `../showeq-web/src/ui/concolor.ts` (canonical), `../iced-miseru/src/concolor.rs`, `../showeq/src/player.cpp` — change them together. The daemons deliberately carry no con logic: level ships raw and each client colors it.
Spawn presentation: the list con-colors row text the way legacy showeq does (`showeq/src/spawnlistcommon.cpp` `m_textColor = pickConColor`) — corpses still dim to grey as a type override — plus a leading `ColCon` con-dot column carried over from showeq-web. The map draws per-type glyphs — con-filled circle for NPCs, con-filled square with magenta outline for PCs, hollow yellow square for PC corpses, cyan plus for NPC corpses, tiny brown square for doors, yellow X for drops. Only NPCs go through the batched `drawPoints` path; that is the only populous type, so the other glyphs are drawn per-item on purpose.
